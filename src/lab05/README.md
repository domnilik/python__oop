## 2. Lambda-выражения
**Lambda** — это небольшая анонимная функция, которая определяется одной строчкой кода без использования ключевого слова `def`.

*   **Зачем нужна:** Чтобы не создавать громоздкую именованную функцию там, где логика нужна всего один раз (например, внутри сортировки или фильтрации).
*   **В моей лабе:** Мы использовали лямбды для быстрой настройки правил в методах `sort_by` и `get_summaries`. Это позволило сделать код более лаконичным и читаемым.

## 3. Реализованные функции и стратегии

### Стратегии сортировки и фильтрации (модуль `strategies.py`)
В проекте реализованы гибкие алгоритмы для управления списком счетов через функции-предикаты и ключи:
*   **Сортировка**: реализованы стратегии `by_owner` (по имени владельца) и `by_balance` (по сумме на счету).
*   **Фильтрация**: реализована функция `is_active` для отбора работающих счетов.
*   **Фабрика функций**: реализована функция `limit_filter(min_amount)`, которая создает фильтр по минимальному балансу с использованием механизма **замыкания**.

### Функции высшего порядка (класс `BankOffice`)
Класс-контейнер расширен методами высшего порядка, которые принимают функции в качестве аргументов:
*   **`sort_by(key_func)`**: принимает стратегию сортировки для упорядочивания элементов коллекции.
*   **`filter_by(predicate)`**: использует переданную функцию-предикат для создания нового отфильтрованного объекта `BankOffice`.
*   **`apply(func)`**: применяет произвольную функцию обработки (например, начисление бонусов) к каждому счету в коллекции.
*   **`get_summaries()`**: использует встроенную функцию `map` и **lambda-выражение** для формирования красивых текстовых сводок о счетах.

### Паттерн «Стратегия» и Callable-объекты 
Реализован класс **`InterestStrategy`** — гибкая стратегия начисления бонусов:
*   **Механизм**: использование магического метода `__call__` позволяет экземпляру класса вести себя как функция.
*   **Преимущество**: в отличие от обычной функции, этот объект может хранить настройки (например, разный процент бонуса) и передаваться напрямую в метод `apply()`.

## Вывод
В ходе выполнения лабораторной работы были изучены и применены на практике следующие концепции:
*   **Передача функций как аргументов**: реализована возможность гибкой настройки поведения методов коллекции через внешние функции-делегаты.
*   **Lambda, map, filter**: освоены инструменты функционального программирования для лаконичной фильтрации, сортировки и трансформации данных «на лету».
*   **Функции высшего порядка и замыкания**: реализована фабрика функций для динамического создания фильтров с заданными параметрами.
*   **Паттерн «Стратегия»**: изучен способ инкапсуляции алгоритмов в вызываемые (callable) объекты, что позволило интегрировать функциональный подход в объектно-ориентированную модель банковской системы.
*   **Fluent Interface**: реализованы цепочки вызовов (Method Chaining) для последовательной и читаемой обработки коллекции объектов.
