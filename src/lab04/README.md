# Лабораторная работа №4: Интерфейсы и абстрактные классы (ABC)

Абстрактный класс — это класс, который не предназначен для создания экземпляров. Он служит шаблоном для других классов. Абстрактный класс может содержать абстрактные методы — методы, объявленные, но не реализованные. Любой класс, наследующий абстрактный класс, обязан реализовать все его абстрактные методы, иначе он тоже останется абстрактным.

В Python абстрактные классы создаются с помощью модуля abc:
* ABC — базовый класс для создания абстрактных классов.
* @abstractmethod — декоратор, помещающий метод как абстрактный.

Интерфейс — это абстрактный класс, содержащий только абстрактные методы (без реализации). Интерфейс задаёт контракт: класс, реализующий интерфейс, обязуется предоставить все его методы. Это позволяет различным классам иметь единое поведение.

### Полиморфизм через интерфейсы
Полиморфизм — способность объектов разных классов отвечать на один и тот же вызов метода по-разному. При использовании интерфейсов полиморфизм достигается естественно: программа работает с объектами через общий интерфейс, не заботясь об их конкретном типе.

### Цель работы:
Познакомиться с абстрактными базовыми классами (ABC), освоить понятие интерфейса как контракта поведения, научиться задавать обязательные методы и реализовывать полиморфизм через единый интерфейс.

### Интерфейсы interfaces.py (ABC)
* Интерфейс: **Printable**, абстрактный метод `to_string()` — обязательно предоставить текстовое представление объекта.
* Интерфейс: **Comparable**, абстрактный метод `compare_to()` — обязательно реализовать логику сравнения.

### Классы и реализация интерфейсов models.py
**Базовый класс BankAccount**
* Реализует базовую логику счета: номер, владелец, баланс.
* Использует инкапсуляцию: атрибуты защищены (_balance), доступ к ним настроен через декораторы @property (геттеры).
* Содержит статический счетчик total_accounts для отслеживания общего количества созданных счетов.

**Класс SavingsAccount (Сберегательный счет)**
* Наследует BankAccount.
* Реализует интерфейсы Printable и Comparable.
* Добавляет специфическое поле interest_rate (процентная ставка).
* Использует super().__init__ для вызова конструктора родителя.

**Класс BusinessAccount (Бизнес-счет)**
* Наследует BankAccount.
* Реализует интерфейсы Printable и Comparable.
* Добавляет уникальное поле overdraft_limit (лимит ухода в минус).

### Демонстрация demo.py

#### Сценарий 1: Данные о счетах и методы интерфейсов
Объекты разных типов (Сберегательный, Бизнес) создаются корректно, имеют свои атрибуты, и интерфейсные методы (to_string) вызываются и работают по-разному.
* Для SavingsAccount выводится процентная ставка.
* Для BusinessAccount выводится лимит овердрафта.
Наблюдаемый полиморфизм: одна и та же команда to_string() приводит к разному поведению в зависимости от типа счета.

#### Сценарий 2: Полиморфизм через интерфейсы
Создается список счетов, который обрабатывается единообразно.
* Используется функция get_priority_account, которая принимает тип Comparable. Она находит счет с наибольшим балансом, не зная, к какому конкретному классу он относится.
* Выполняется проверка isinstance() для подтверждения того, что объекты реализуют нужные интерфейсы.

![Сценарий 2](./src/images/lab04/image2.png)

#### Сценарий 3: Сортировка коллекции
Демонстрация работы со структурированными данными. Коллекция счетов сортируется по балансу (от большего к меньшему). Это доказывает корректную работу геттеров и логики сравнения.

![Сценарий 3](./src/images/lab04/image3.png)

#### Сценарий 4: Фильтрация по интерфейсу
Обработка смешанных («грязных») данных. Программа фильтрует список, содержащий счета, строки и числа.
* Если объект реализует Printable, он выводится в консоль.
* Если объект не соответствует интерфейсу (например, int или str), он безопасно пропускается.
Это демонстрирует надежность кода и умение работать с интерфейсами как с фильтрами.
